# 第 8 步：对齐与归一化

实验脚本：[step8_alignment.py](step8_alignment.py)

```bash
pixi run python docs/learn/step8_alignment.py
```

第 5 步的结论是：位置、绝对尺度、水平朝向从图里看不出来，应该在比较前消除；上下方向和各部分比例看得出来，应该扣分。

第 7 步说明，不归一化这些无关影响的话，这些看不出来的差异会主导奖励。这一步比较几种具体的消除办法。

## 1. 三个要选的部件

对齐分三件事，各有几种做法：

| 部件 | 做法 | 说明 |
|---|---|---|
| 平移 | 包围盒中心 | 包围盒（各轴最小值到最大值）的中点移到原点 |
| | 质心 | 所有采样点的平均位置移到原点。采样按面积进行，所以质心是按面积加权的 |
| 尺度 | 包围盒对角线 | 除以包围盒对角线长度 |
| | 单位球（benchmark 的做法） | 除以离质心**最远**那个点的距离 |
| | RMS 半径 | 除以所有点到质心距离的**均方根**，即 √(平均距离²) |
| 旋转 | 4 个水平角 | 绕竖直轴转 0°、90°、180°、270°，取距离最小的 |
| | 24 个轴对齐旋转（benchmark 的做法） | 把三根坐标轴任意互换、翻转方向，但不含镜像，共 24 种，取最小 |

平移和尺度的两种做法是配套使用的：包围盒中心配包围盒对角线，质心配单位球或 RMS 半径。

## 3. 从结果读出的结论

### 对齐解决了平移、缩放、整 90° 的水平旋转

所有对齐方式下，这三种破坏都回到了噪声底，完全不扣分。这正是第 7 步发现的问题的解法。

### 水平转 30° 补偿不了

枚举 0°、90°、180°、270° 只能补偿 90° 的整数倍。转 30° 后扣分很重，甚至比不对齐时还重：包围盒变大了，物体被缩得更小，形状错位更严重。考虑到目标网格和模型的建模习惯都是沿坐标轴摆放，这种情况应该不多，暂时接受。

### 包围盒归一化对"多出来的部分"过于敏感

这是实验里最重要的发现。包围盒只由最外面的几个点决定。只要生成结果在某个方向多伸出一点东西，包围盒就会变大、中心就会偏移，**整个物体**都会被错误地平移和缩放，于是所有部分都对不上：

- 桌面上多一个 20cm 方块：包围盒归一化扣了 7.5 倍噪声底，质心类方法只扣约 2 倍。
- 远处多一个 2cm 小方块：包围盒归一化扣了 33.7 倍，比上下颠倒还重；RMS 半径只扣 1.1 倍。

模型生成的脚本很可能出现这种情况，比如多建一个地面、一个底座，或者留下一个忘了删的小物体。用包围盒归一化，一个很小的多余物体就能让一个形状基本正确的回答得到很低的分。

单位球归一化也会受影响（3.7 倍），因为它的尺度由最远的那个点决定。**RMS 半径**按面积对所有点取平均，一小块离群物体只占很少的面积，对它影响很小。

### 24 个旋转会原谅上下颠倒和侧放

用 24 个轴对齐旋转时，上下颠倒和侧放都回到了噪声底，完全不扣分。而 4 个水平角下，它们分别扣 9 倍和 21 倍。第 5 步说过，上下方向在参考图里看得很清楚，所以不应该原谅。

## 和奖励的关系

综合起来，建议的对齐方式是 **质心 + RMS 半径 + 4 个水平角**：

1. 平移、缩放、整 90° 的水平旋转完全不扣分。
2. 上下颠倒、侧放、比例错误、缺失部件都会扣分。
3. 一小块多余物体不会让整个物体错位。

需要注意两点：

- RMS 半径会让数值的量纲和现在不同，噪声底从 0.0073 变成约 0.025。这个数值要和第 9 步的奖励映射一起调整。
- 当前目标是让模型建出的形状大致正确，所以噪声底随物体变化这类数值细节（第 6 步）暂时不追究。

## 检验问题

参考图看得出上下方向，奖励该不该原谅上下颠倒？

## 解答

不该原谅。上下方向是图里能看出来的信息，模型应该做对，所以只枚举 4 个水平角，不用 24 个旋转。只要模型把物体正立放好，它在 benchmark 上的得分不会因此变差：4 个水平角包含在 24 个旋转之中，取最小值时，24 个旋转的结果不会比 4 个水平角差。
