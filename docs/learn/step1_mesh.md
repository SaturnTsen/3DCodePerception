# 第 1 步：网格（mesh）是什么

实验脚本：[step1_mesh.py](step1_mesh.py)

```bash
pixi run python docs/learn/step1_mesh.py temp/review/SimpleDeskFactory.npz
```

## 1. 两个数组就能描述一个形状

计算机里的 3D 物体通常只表示**表面**，不表示内部，就像一个空心的壳。这个表面由很多小三角形拼成，存储时只需要两个数组：

| 数组 | 形状 | 含义 |
|---|---|---|
| `vertices`（顶点） | N×3 浮点数 | 每行是一个点的坐标 (x, y, z)，单位米 |
| `faces`（面） | M×3 整数 | 每行是一个三角形，存的是 3 个**顶点的下标**，不是坐标 |

用模型训练里熟悉的方式类比：`faces` 就像 token id，`vertices` 就像 embedding 表。三角形本身不存坐标，而是用下标去"查表"拿到 3 个点。

## 2. 看真实的书桌

书桌网格的输出如下：

```
vertices: (1560, 3)    faces: (1020, 3)
第 0 个三角形 = 顶点 [1, 4, 7]，坐标是：
  [ 0.3726 -0.592   0.3356]
  [ 0.3726  0.592   0.3356]
  [-0.3726  0.592   0.3356]
```

这 3 个点的 z 都是 0.3356，x 和 y 分别在 ±0.37、±0.59。它们是**桌面上表面**的三个角。第 1 个三角形 `[1, 7, 10]` 补上了第四个角。所以整个桌面上表面就是一个矩形，只用 2 个三角形表示。平的表面不需要很多三角形，弯曲的表面才需要很多。

书桌只有 1020 个三角形，而蘑菇（`MushroomFactory`）有约 338 万个，因为它表面布满了细小的曲面细节。

## 3. 一个值得注意的现象：重复顶点

输出里的前 3 个顶点**坐标完全相同**。原因是 GLB 文件会为同一个位置在不同的面上各存一份顶点，以便每个面拥有自己的法线方向和贴图坐标，让棱角渲染得锐利。所以书桌的顶点数（1560）比三角形数（1020）还多，而一个封闭的网格通常是三角形多、顶点少。

**结论：顶点数量不能说明形状的复杂程度，它和存储方式有关。**

## 4. 同一个形状，可以有完全不同的网格

脚本里用两种方式表示同一个 1×1 的正方形：

| 划分方式 | 顶点数 | 三角形数 | 面积 |
|---|---|---|---|
| 粗划分 | 4 | 2 | 1.0 |
| 细划分 | 9 | 8 | 1.0 |

两种网格描述的是**完全相同的表面**，但两个数组的长度和内容都不一样。

## 和奖励的关系

模型生成的脚本和目标 GLB 是两套完全独立的建模过程。即使形状一模一样，顶点数、顶点顺序和三角形划分也几乎不可能相同。

## 检验问题

为什么不能直接逐个顶点比较两个网格（比如对两个 `vertices` 数组求差）？应该用什么方式来比较？

## 解答

朝向和单位（尺度）确实可能不同，这两点在第 8 步"对齐与归一化"里处理，但不是这道题的核心。

**核心原因是：就算朝向和单位完全一致，两个数组也无法逐个对应。** 上面的正方形，粗划分有 4 个顶点、细划分有 9 个顶点，形状完全相同，但数组长度不同，无法相减。即使长度碰巧相同，顶点的排列顺序也是任意的，"第 i 个顶点对第 i 个顶点"的对应关系本身就不存在。

**替代方式**：不比较顶点，而是比较**表面**。在两个表面上各均匀撒一批点，对每个点找另一边离它最近的点，看距离有多远。这不依赖顶点的数量和顺序，也就是 Chamfer 距离的思路（第 6、7 步展开）。
